# The components programme — the ledger

_Generated from `ledger.json` by `render-ledger.mjs`. Do not edit this file; edit the JSON and re-render._

This JSON is the single record of the plan; the Markdown beside it is generated from it. Every PR of the programme carries its slot id in its title. A slot is done only when its evidence is written here: the PR number, the prod time and the acceptance test's result line. The agent may change only `status` and `evidence`; a slot is added or its scope changed only through a dated line in `changes` carrying the operator's word, and `scopeHash` (the first 12 hex characters of the SHA-256 of `scope`, rewritten by `node docs/plan/render-ledger.mjs --rehash`) makes such a change a deliberate diff. `pages` lists the routes a done slot serves from rows. The test `lib/design/plan-ledger.test.ts` fails the build when a page is served from rows without a done slot that lists it, when a slot's `scopeHash` does not match its scope, and when the record is malformed. Plan page: artifact 4d804904-63ad-4ddf-8d37-67dcb2d2fcc8.

## Rules the ledger enforces

1. Decision scan before a slot starts: Fixed by · Defaults I take · Needs your word; a non-empty third line stops the slot until the operator answers in one or two sentences with a default. Overnight = decision-free slots only.
2. Gates on every PR: tsc 0 · lint 0 errors · full vitest · cf:build and the dry-run Total Upload quoted (alarm at 80% of 64 MiB) · a browser run on the local server · a review page · a component test from a saved document · parity output for every deleted route file · a fresh-context Sonnet reviewer before merge.
3. No page-specific component; a section that fits none is a question. Sources from the catalogue, never a query. Every component carries a Condition, an authorization scheme, a build option, template options with a preset, and Utilization with History.
4. Every shared object shows where it is used and its history and cannot be deleted while referenced. Text is escaped by default. Exports key files by stable id. Any apply is atomic, validated, staged, refused while locked.
5. Agents: Sonnet or Haiku, one at a time, writing incrementally; building is done directly; fan-outs announced before and accounted after; none above 60% usage.
6. Session ritual: read the rules, the ledger and the git log; name the next slot; start the dev server; smoke-test; one slot at a time; end by writing evidence and the handoff.
